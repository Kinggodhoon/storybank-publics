02 / Principles

설계 원칙

  • BOUNDARYDB 중심의 권한 경계모든 테이블에 RLS(행 수준 보안) 적용. 업무 규칙이 걸린 쓰기는 호출자 권한을 먼저 확인하는 DB 함수로만 처리.
  • WRITES쓰기 경로는 세 가지본인 정보의 단순 쓰기, 규칙이 있는 DB 함수, 시스템 작업으로 구분. 코드에서 경로가 바로 드러나는 구조.
  • HISTORY기록 불변 원칙에피소드 버전, 권리 기록, 이용 기록, 감사 로그는 추가만 허용. 주문에는 주문 시점 조건을 복사해 보관.
  • CATALOG공개 목록 자동 갱신승인·권리·동의 변경 시 같은 트랜잭션에서 공개 목록 재생성. 같은 원고의 동시 변경은 순서대로 처리.
  • SETTINGS설정 기반 운영 규칙가격, 배분율, 한도, 동의 문서 버전을 설정값으로 관리. 정책이 바뀌어도 데이터베이스 구조 변경 불필요.

03 / Files

원고 파일과 열람

  1. 예약DB가 경로·형식·크기·한도·저장 용량을 확인하고 예약
  2. 업로드브라우저가 서명된 링크로 저장소에 직접 업로드
  3. 처리처리 중 표시로 중복 처리를 막고, 파일 형식 확인과 본문 추출
  4. 등록올린 파일이 예약 내용과 같을 때만 원고와 본문 기록
  5. 열람열람 기록을 남긴 뒤 60초 유효 링크 발급, 변경된 파일은 거부

원문 직접 조회 불가. 본문은 전문 조회·문단 조회 함수로만 제공하며, 호출 시마다 열람 기록 저장. 관리자도 동일하게 적용.

04 / Performance

캐시와 운영

Cache

공개 목록만 캐시

모든 사용자에게 같은 공개 목록만 캐시. 관리자 수정 시 즉시 캐시 삭제. 동의서 기한이 날짜 단위라 캐시는 한국 시간 자정을 넘기지 않음.

Capacity

무료 플랜으로 시작

Supabase 무료 플랜(DB 500MB·저장소 1GB)에서 원고 90편 수용, 용량 부족 시 유료 플랜 전환. 무료 플랜은 7일 미사용 시 일시정지. 상업 이용이라 Vercel Pro 필요, AI 사용량 비용 별도.

Region

서울 리전

Supabase 서울 리전. 운영 데이터베이스 구조와 검증 환경의 일치 확인(9.30).

i18n

한국어·영어

공개 화면은 같은 구조의 영어 화면 제공. 원고와 요약은 번역하지 않음.
