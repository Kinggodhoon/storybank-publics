Service Planning Brief

스토리뱅크
서비스 기획서

인터뷰 원고를 에피소드 단위로 나누고, 권리와 동의를 검증한 뒤, 필요한 회차만 구매하는 스토리 라이선스 서비스. 본 문서는 사업 방향, 서비스 컨셉, 사용자와 흐름, 거래·권리 원칙을 정리합니다.

투입 원고
최대 90편 판매 동의 범위 확인분
거래 단위
에피소드(회차)
납품
10.30 계약 납품물 C1–C5

01 / Background

배경과 문제

좋은 이야기는 원고 한 편 안에 여러 장면으로 흩어져 있음. 원고 단위 거래로는 필요한 장면을 찾기 어렵고, 이용 허락 범위를 확인하기도 어려움.

Problem 1

장면 단위 탐색 불가

원고 단위로는 "새벽에 불을 켜는 떡집" 같은 장면 검색 불가. 장면과 원문 위치의 연결이 있어야 검색·인용 가능.

Problem 2

권리 관계의 복잡성

구술자·작가·출판권자가 얽혀 원고마다 공개·판매 범위가 다름. 동의 증빙이 없는 원고의 판매 차단 장치 필요.

Problem 3

거래 기록의 부재

전문 열람자·열람 시각, 판매 버전의 기록이 없으면 정산과 분쟁 대응 불가.

02 / Goals

서비스 목표

  • GOAL 1원하는 스토리를 검색원고를 에피소드로 나누고 원문을 연결해, 필요한 장면을 검색 및 요약으로 바로 찾을 수 있게 구현.
  • GOAL 2스토리의 검증권리 기록과 동의 증빙이 없는 에피소드는 공개 및 판매를 금지.
  • GOAL 3거래 이력 관리주문, 결제 확인, 이용 기록, 정산, 지급을 하나의 흐름으로 기록.

성과 측정. 정량 성과는 공인기관(KTR 등)에서 측정. 측정 항목과 목표치는 발주자와 협의 후 확정 예정(U3).

03 / Concept

서비스 컨셉

분할 · 검증 · 거래

검수를 마친 에피소드만 공개 목록에 게시. 도서관 목록 카드처럼 출처와 권리를 명확히 보여 주되, 카드 한 장으로 가볍게 훑어볼 수 있는 구성.

01 · 분할

에피소드 분할

원고 업로드 시 본문과 장·절·문단 구조 추출. 문단 범위로 에피소드를 생성하고, 버전별로 저장해 원문 위치 유지.

02 · 검증

권리·동의 검증

권리 판정을 버전별로 기록하고 동의서의 범위·기한 확인. 조건 미충족 시 판매 자동 중지.

03 · 거래

회차 거래·정산

필요한 회차만 선택해 주문. 결제 확인 시 이용 기록과 저작권자 몫의 정산 내역 자동 생성.

04 / People

사용자와 역할

공급 · 수요 · 운영

공급

스토리 작성

발주사 보유 인터뷰 원고(판매 동의 범위 확인분), 직접 쓴 원고를 등록하는 회원 작가.

수요

스토리 구매

다큐멘터리·드라마·영화·웹툰·출판·교육 분야에서 소재와 장면을 찾는 기획자·작가.

사용자하는 일볼 수 있는 것
방문자탐색, 에피소드 요약과 공개 발췌 보기제목·승인 요약·공개 발췌·판매 상태
무료 회원검색, 원고 올리기, 유료 전환 신청방문자와 같음 + 내가 올린 원고의 진행 단계
유료 회원회차 선택·장바구니·주문, 전문 읽기공개 목록의 전문, 구매한 에피소드는 구매 시점 버전
원고 제공 회원원고 등록, 책임 고지·외부 AI 처리 동의내 원고의 접수·검수·반려 사유
관리자원고 검수·분할·승인, 권리·동의서, 상품·주문·정산, 회원 관리관리자 화면 전체(열람은 기록으로 남음)
저작권자(시스템 외부) 정산 대상정산 내역과 지급 기록의 기준

대표 시나리오

  • BUYER다큐 작가의 소재 탐색"시장" 검색 → 요약 확인 → 원고 상세에서 회차 2개 선택·주문 → 결제 확인 후 내 서재에서 전문 열람.
  • WRITER회원 작가의 원고 등록DOCX 원고 업로드·책임 고지 동의 → 마이페이지에서 접수·검수·분할·공개 단계 확인 → 반려 시 사유 확인.
  • ADMIN관리자의 원고 공개원고 접수 → 권리 기록 → 문단 범위로 에피소드 생성·승인 → 조건 충족 시 판매 상태로 자동 전환.

05 / Flow

핵심 흐름

원고 등록부터 판매까지

  1. 회원 · 관리자원고 등록TXT·DOCX·PDF, 책임 고지 동의
  2. 시스템본문 추출문단·장·절·쪽 구조와 원문 지문(해시)
  3. 관리자접수·분할문단 범위로 에피소드·버전 생성
  4. 관리자권리·승인권리 기록, 동의서, 버전 승인
  5. 시스템상품 등재판매 조건 확인 후 판매 상태 결정
  6. 회원탐색·선택검색, 회차 선택, 장바구니
  7. 회원 · 관리자주문·결제 확인중복 주문 방지, 관리자 결제 확인
  8. 회원 · 관리자서재·정산전문 읽기, 정산 내역과 지급 기록

알파 서비스에서 전 과정 동작 확인(2026.09.30, 로컬 시연 환경·합성 데이터 기준). 배포 주소는 계정 준비 후 공유. AI 분할·태그·의미 검색은 다음 단계에서 추가.

07 / Rights

권리·동의·개인정보 원칙

  • R1회원 업로드업로드 시 동의한 책임 고지 범위 안에서 요약·발췌 공개 및 에피소드 판매. 저작권 책임은 업로드 회원에게 있으며 계약서는 받지 않음.
  • R2관리자 등록보유 원고는 동의서 파일(스캔 이미지 가능)로 증빙. 확인된 동의서의 범위와 보관 기한 안에서만 공개·판매.
  • R3판매 차단권리 기록 또는 필요한 범위의 동의가 없으면 "판매 차단(동의 없음)"으로 전환. 이용 제한이 있으면 "조건부 판매"로 전환하고 제한 내용 표시.
  • R4외부 AI 처리외부 AI 처리에 동의한 원고만 AI 분할·임베딩에 사용(다음 단계 적용).
  • R5열람 기록전문·원본 파일·동의서 열람 시 열람자와 시각 기록. 파일은 60초 유효 링크로만 제공.
  • R6버전 보존에피소드와 권리 기록은 수정 없이 새 버전으로 추가. 주문에는 주문 시점의 버전·권리·가격을 복사해 보관.
  • R7개인정보요약·발췌에 실명 사용 금지. 탈퇴 시 개인정보 마스킹, 거래 기록은 전자상거래법에 따라 5년 보관.

08 / Scope

개발 단계와 범위

도메인별로 DB → API → 화면 → 합성 데이터를 한 단계로 개발

단계내용상태
B1 기반권한 경계, 감사 로그, 오류 코드, 요청 추적, 통합 테스트완료 9.29
B2 회원가입·로그인·재설정, 동의 기록, 마이페이지, 유료 전환, 회원 관리완료 9.29
B3 기본 흐름원고 업로드·추출 → 분할 → 승인 → 상품 → 탐색 → 주문 → 정산 → 서재완료 9.30
B4 AI 처리작업 대기열, AI 분할·요약, 태그·키워드, 임베딩·의미 검색예정
B5 권리 심화3단계 승인 게이트, 간이 계약 PDF, 외부 AI 전송 통제예정
B6 운영·증빙감사 로그 화면, 내보내기, KPI 측정, 통합 점검예정

B4–B6의 일정과 범위는 개발(D3) 계약과 함께 별도 협의.

10 / Glossary

용어

용어뜻
원고회원이나 관리자가 올린 파일 한 편. 원본 파일은 원문, 추출한 텍스트는 본문이라고 부릅니다.
에피소드 · 회차원고의 문단 범위로 만든 거래 단위. 회차는 원고 안에서의 순서(E1, E2…)입니다.
승인 요약 · 공개 발췌관리자가 승인한 요약, 원문 그대로 인용하는 짧은 문장. 누구나 볼 수 있습니다.
전문에피소드의 본문 전체. 유료 회원과 구매자만 읽습니다.
권리 기록 · 동의서원고의 출판권·공개·2차 활용 판정(버전별)과 그 증빙 파일.
판매 상태등재 대기·판매 차단(동의 없음)·조건부 판매·판매 중·판매 중지·판매 안 함.
이용 기록 · 정산 내역 · 지급 기록결제 확인 때 생기는 구매 증빙, 저작권자 몫, 실제 지급 사실.
